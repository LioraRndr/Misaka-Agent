## 总评（通读完成后写）

**覆盖**：649 个文件全部过了一遍（`coverage.tsv`）。深度不均，如实说明：
- 逐行读：`ai/`、`agent/`、`utils/`、`config/`、`core/` 顶层全部、`core/extensions`、`core/platform`、`core/tools`（bash/read/write/web_fetch/download_file/office）、`core/moa`、`core/compaction`、`core/export_html`、`core/research` 的 workflow/runs/bundle/wiring、`core/network/sister_runtime`、`core/web` 主链路（tool/dispatch/runtime/config）。
- 结构扫描 + 风险模式检索 + 抽读：`core/web` 的各后端与 browser/vault、`core/subagent`（runtime/policy 抽读较多）、`core/network` 其余、`core/skills`、`core/documents`、pi 移植的 grep/find/ls/truncate/edit_diff、office 写入器、`extensions/misaka_lcm/host`、`cli/`、`ui/`（interactive_mode 与 panel 做了度量和抽读）。`extensions/misaka_lcm/native`（15.7k 行 Hermes 机械移植）按 vendor 对待，只记了体量与耦合（Q-136/Q-137）。
- 凡是能跑的判断都跑过：真实 home 上计时/测内存（Q-093、Q-131）、构造输入复现（Q-015、Q-104、Q-110、Q-114、Q-123、Q-124、Q-132），也有两处疑点经实测被推翻、没有入账（per-turn deepcopy 开销；plan 模式 `rg --pre` 绕过——被工作区路径守卫拦下）。

**计数**：141 条。BUG 23（H 1 / M 13 / L 9），屎山 49，不优雅 65，治标 4。

**一句话评价**：局部写得很认真、甚至过度认真，整体在往"补丁摞补丁"的方向长。单个函数的防御、注释和边界处理常常好于一般项目（web、documents、download_file、office 的原子提交都能看出功力）；但系统层面同一件事普遍有两到五份实现，改一处漏几处，于是"修了 B56 漏了 `terminate_orphaned_group`"（Q-110）、"写好了 `without_credentials` 却没接到 bash 和 MCP"（Q-121/Q-086）这类问题反复出现。

**最该先修的具体缺陷**（都能复现）：
1. Q-015 脱敏：文本里出现一个 `://` 就跳过大半规则，含 URL 的日志/笔记里的密码原样进账本和 git。
2. Q-121 / Q-086：模型的 bash 和第三方 MCP 子进程拿到 `.env` 里全部 API key；现成的 `without_credentials` 只用在了 DDGS/浏览器上。
3. Q-123：`read`/`edit` 不查文件类型也不设上限——FIFO 让工作线程永久卡死（edit 连 Esc 都救不回），`/dev/zero` 直接 OOM。
4. Q-110：进程身份漂移的修复漏了 `terminate_orphaned_group`；漂移一旦发生，卡住但仍活着的 worker 会被"认定已停"、不被杀掉，卡片却被回收重派。
5. Q-132：`/research 1968 …` 直接报错，`/research 3 main causes …` 静默把数字吃掉——研究的是另一个问题。
6. Q-104：`/login` 里 8 个纯 API-key 的内置 provider 选不到。
7. Q-048：OpenAI 兼容适配器对任何 provider 兜底读 `OPENAI_API_KEY`，把 OpenAI 的 key 发给别家端点。
8. Q-056：Gemini/Vertex 以"外层会重试"为由关掉 SDK 重试，而外层重试函数零调用——provider 层零重试、`retry.provider.maxRetries` 对它无效（会话层自动重试仍在）。
9. Q-028、Q-081、Q-083、Q-009、Q-020、Q-124、Q-114：见各条。

**系统性问题**（每条对应多条发现，修一处不够）：
- **同一件事多份实现**：脱敏正则 4 份（Q-118）、AbortSignal 4 套（Q-061）、OAuth 回调服务器 5 个（Q-067）、文件锁重试 3 份（Q-096）、工具性质表 9 张（Q-130）、错误文本分类器 5 套（Q-114）、schema 版本机制 3 套（Q-112）、read_field 私有副本十几份（Q-078 等）、租约锁字符串 5 种格式（Q-133）、预算心跳 2 套（Q-135）、不可信数据围栏 2 套（Q-134）。

- **注释当台账**：行号引用、bug 编号、"以前如何"的叙述（Q-069/Q-097），加上 harn/pi/Hermes 命名残留（Q-042/Q-105/Q-107/Q-129）。
