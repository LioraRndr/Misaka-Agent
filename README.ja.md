取りまとめ役の **Last Order**（打ち止め）と一緒に問いを分解して研究計画を練り上げ、研究の各分野の調査を、報告・連絡・相談を得意とする **Sisters**（妹達）に割り振ります。専門家たちの調査報告を集約して読み込み、執筆し、審査員の前で答弁を終え、結論が覆いきれない方向を新たな研究へと転じます。研究の枝からなるグラフはグラフ理論のアルゴリズムで管理され、最終報告は研究論文としてプロジェクトフォルダに保存されます。すべての引用は出典までたどることができます。

## クイックスタート

```sh
uv tool install "misaka[providers] @ git+https://github.com/Luciole-Studio/Misaka-Agent.git"

mkdir my-research
cd my-research
misaka setup     # サインイン、モデル選択、最初の二人の Sister を作成
misaka           # MISAKA を起動し、/research と入力
```

動作環境は macOS、Linux、Windows（x86_64 / arm64）です。[uv](https://docs.astral.sh/uv/)、git、[ripgrep](https://github.com/BurntSushi/ripgrep)、[fd](https://github.com/sharkdp/fd)、poppler のインストールと、モデルプロバイダ（API キー、または ChatGPT、GitHub Copilot のサブスクリプション）が必要です。Claude アカウントでのサインインにも対応しており、その利用分は Anthropic によりトークン単位の追加利用として課金されます。インストールは本リポジトリから行ってください。PyPI の `misaka` は無関係のパッケージです。

[はじめに](docs/getting-started.ja.md)では、インストールの手順から最初の研究の問いまでを順を追って説明しています。

## 研究の進め方

> *計画ができたよ！あなたが「いいよ」って言ったらすぐ始めるから！ってミサカはミサカは計画書を両手で差し出してみたり。*

一回の研究は可能性からなるグラフです。あなたの問いが根ノードとなり、結論が退けた可能性の一つひとつが、層ごとにその下のノードとなります。

<p align="center">
  <img src="assets/research-graph.ja.svg" alt="一回の研究はグラフです：あなたの問い、第 1 層に別の仮説・別の方法・問いそのものへの批判、第 2 層にそこから選ばなかった道、二つの線が挙げて一度だけ研究する問い、同じところでの合流、そして最終報告" width="820">
</p>

1. **各ノードは完結した一つの研究です。** Last Order はあなたと計画を協議し、同意を得てから実行に移します。専門家の資料が提出されるまで、Last Order は問いを下位の問いと前提となる問いに分解するにとどめ、結論を先取りしません。Sisters はカードを並行して進め、発見ごとに出典を記録し、Last Order はそれを精読したうえで結論を書きます。
2. **レッドチームと分岐レビュー。** レッドチームの Sister が事実と推論を検証し、結論が明言しない箇所を指摘します。続いて新しいセッションで分岐レビューを行い、結論が退けた可能性と残された欠落を区別します。Last Order はノード内で異議の一つひとつに応答して欠落を補い、改訂した結論は再び審査に付されます。
3. **研究グラフの展開。** 前提を異にする真の代替可能性のみが、Last Order のセッションから分岐して新たなノードとなり、それまでの推論をすべて継承します。各ノードには Last Order、Sisters、レッドチームが備わり、設定した深さまで層ごとに展開します。複数の筋が提起した問いは一度だけ研究され、同じ可能性が二度開かれることはなく、同じ地点に至った筋は合流点で対質させます。
4. **報告。** すべてのノードが閉じると、Last Order は全体を通覧し、研究が到達した論点を一篇の研究論文に構成します。注と参考文献を備え、付録にはすべての研究の筋、答えが引き受けた代償、採られなかった道を記録します。草稿は独立したレッドチームの審査を経て、Last Order が異議の一つひとつに裁定を下し、最終稿とします。

研究の深さ、並行数、進行の確認と再開については、[研究ガイド](docs/guide/research.md)（英語）をご覧ください。

## 研究の成果物

> *引用した資料は、すべて確かめられる場所に綴じてあります、とミサカは報告します。*

成果物はすべてプロジェクトフォルダに書き込まれます。

```text
my-research/
├── final/<run>-final.md     最終報告（引き受けた代償と採られなかった道を含む）
├── final/<run>-sources/     報告が引用したすべてのファイル（元の場所へのリンク）
└── nodes/<node>/            研究ごとのディレクトリ
    ├── plan.md              Last Order の研究計画と Sister の選定理由
    ├── cards/<card>/        各 Sister の成果とレッドチームの批評
    ├── synthesis.md         結論（改訂版は synthesis-2.md 以降）
    └── SOURCES.md           結論が引用したファイルと、それぞれが支える主張
```

MISAKA がコミットするのは、あなたが求めたときに限られます。プロジェクトが git リポジトリであれば、`/commit` がファイルを提示し、あなたの確認を経てコミットします。

## 主なコマンド

| 用途 | コマンド |
|---|---|
| MISAKA を起動する | `misaka` |
| 研究を開始する | `/research`、続けて問いを入力 |
| 研究の確認・中断・再開 | `/research status`、`/research stop`、`/research resume` |
| 特定の Sister と対話する | `/sister 10032` |
| Sister を作成する | `misaka create 10036 --desc "計量経済学と因果推論"` |
| 文書を索引化する | `misaka doc scan sources/` |
| モデル選択、サインイン | `/model`、`/login` |
| すべてのコマンドを表示する | チャットで `/`、端末で `misaka --help` |
| パネルのキー操作を表示する | `ctrl+b` に続けて `?`（[パネルガイド](docs/guide/panel.md)を参照） |
| 更新する | `misaka update --apply` |

すべてのコマンドは[コマンドリファレンス](docs/reference/commands.md)（英語）に掲載しています。

## データと費用

MISAKA が保存するデータはすべてお使いのマシン上にあります。設定、認証情報、履歴は `~/.misaka/` に、研究の成果物はプロジェクトフォルダに置かれます。プロンプトは設定したモデルプロバイダにのみ送信されます。ウェブ検索は設定した検索サービスに送信され、未設定の場合やサービスが失敗した場合は Exa、Parallel、Firecrawl、Keenable の無料公開枠を利用します（`misaka web set keyless_fallback false` で無効化できます）。文献スキャンでは、問いの検索語が OpenAlex に送信されます。MISAKA はテレメトリを一切送信しません。

研究の規模は大きくなりえます。初期設定では最大四つの枝が同時に動き、各枝で最大四人の Sister が（メモリの許す範囲で）並行して作業するため、深い研究では多数のモデル呼び出しが発生します。費用を抑えるには研究の深さを小さくし、すべての研究を通じた上限を設けるには `~/.misaka/settings.json` に `research.token_cap` を設定してください。

## 名前の由来

MISAKA の名は、鎌池和馬『とある魔術の禁書目録』『とある科学の超電磁砲』に由来します。原作において妹達（シスターズ）は「超電磁砲」御坂美琴のクローンであり、ミサカネットワークを通じて記憶を共有しています。

| 原作 | MISAKA |
|---|---|
| **御坂美琴**、すべての妹達のオリジナル | `MISAKA.md`：各エージェントが自身の設定に先立って読み込む共通の人格 |
| **妹達（シスターズ）**、検体番号で呼ばれる：ミサカ10032号、10033号…… | あなたの専門家。それぞれが番号、専門分野、固有の `SOUL.md` を持ちます |
| **打ち止め（ラストオーダー）**、ミサカ20001号、ネットワークの上位個体 | あなたが対話する取りまとめ役 |
| **ミサカネットワーク**、一人が学んだことを他の妹達も思い出せる | プロジェクト内の会話。すべてのエージェントが検索できます |

本 README の「とミサカは報告します」といった一節は演出です。各エージェントの話し方はそれぞれの `SOUL.md` によって決まり、妹達と同じ口調にするには `SOUL.md` に一行加えるだけで足ります。

MISAKA は独立したプロジェクトであり、原作者および出版社とは一切関係がなく、公認も受けていません。

## 技術的基盤

MISAKA のエージェントカーネルは [pi](https://github.com/earendil-works/pi) の Python 移植であり、パネルは [herdr](https://github.com/herdrdev/herdr) の移植です。各ペインの端末エミュレーションには [ghostty](https://github.com/ghostty-org/ghostty) の端末ライブラリを用いています。長い会話の管理は [hermes-lcm](https://github.com/stephenschoettler/hermes-lcm)、文書構造の解析は [PageIndex](https://github.com/VectifyAI/PageIndex) を基盤とし、ウェブツールとスキルは [Hermes Agent](https://github.com/NousResearch/hermes-agent) から、Office 対応は [FrontierAgent](https://github.com/ApodexAI/FrontierAgent) から移植しています。各部分の出所は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) に記録しています。

MISAKA が pi を基盤とするのは、カーネルが簡潔で、成熟したコミュニティによって保守されており、上流の更新に直接追随できるためです。MISAKA のグラフが扱うのは研究の内容と可能性であり、ノードは完了した一つの研究、エッジは推論を携えて分岐した一つの問いかけです。
